# 热衡 · 城市供热投诉与室温监测数据可比性分析台

面向监管分析员的本地优先分析工具：判断一个小区的低温投诉究竟对应**持续供热不足**、**局部设备故障**，还是**监测与投诉资料无法可靠对齐**。

工具在浏览器中导入室温读数、气象观测、供热企业工单和热线投诉等 CSV / JSON 样例，先建立「楼栋 × 供热日」的监测覆盖面作为总体分析底表，再把可可靠关联的投诉作为解释线索挂接进去。覆盖不足的楼栋单独标为「无法判断」，不会被读成"没有供热问题"。

**技术栈**：React 19 + TypeScript + Vite，IndexedDB（idb）本地持久化，WebWorker 完成文件解析、时间窗匹配与基线计算。纯静态前端，不上传任何真实住户资料。

## 快速开始

### 方式一：Docker（推荐）

```bash
docker compose up --build -d
# 打开 http://localhost:8080
```

或直接使用 Dockerfile：

```bash
docker build -t heat-comparability-console .
docker run --rm -p 8080:8080 heat-comparability-console
```

健康检查：`GET http://localhost:8080/healthz` 返回 `ok`。

### 方式二：本地 Node（Node 22+）

```bash
npm install                     # 已配置 npmmirror 源
npm run samples                 # 重新生成随题样例（可选，仓库已包含）
npm run dev                     # 开发模式 → http://localhost:5173
```

生产预览：

```bash
npm run build                   # 类型检查 + 打包到 dist/
npm run preview                 # → http://localhost:4173
```

> **测试账号**：本工具是纯前端本地应用，没有登录体系，也无服务端账号。所有操作在浏览器内完成，也就不存在需要提交给评测的测试账号或口令。如需从干净状态开始，见文末「重置工作区」。

## 5 分钟验收路径

1. **来源登记** → 点击「导入随题样例」。
   - 载入 7 个文件：登记册、气象、核心读数、准点工单、投诉、补录工单、迟到读数。
   - 每个批次可点开查看 **SHA-256 哈希、字段解释、时间覆盖、每日行数分布、原始行预览、坏行/去重计数**。
2. **覆盖对齐** → 查看「楼栋 × 供热日」覆盖率矩阵。
   - 11 号楼、2 号楼显示为「无探头」；7 号楼自 1/8 后逐步红掉（探头断线）。
   - 「对齐问题」列出未登记探头 `P-999` 与 2 栋无探头楼栋。
3. **运行** → 选择「指定时刻」并填 `2026-01-20 00:00`（按 UTC+8；截止 = `2026-01-20 08:00`）→ 「启动分析」。
   - 运行在 WebWorker 中执行，完成后自动跳转分析结果。
   - 顶栏出现「2 批迟到数据」：补录工单与迟到读数在截止后到达。
   - 也可以先在运行页点「模拟迟到到达」，把样例里的 late 批次改为“现在到达”，再以较早截止运行，复现同样的覆盖截止提示。
4. **分析结果** → 查看底表、风险表、监测盲区。
   - 点击 5 号楼 `1/10` 单元格 → 当日证据弹窗（24h 曲线、停供工单条、低温片段、覆盖与中断、判定解释、不确定范围、证据引用）。
   - 点击「查看覆盖截止说明」→ 迟到数据不会局部刷新图表或结论卡。
5. **投诉证据** → 点开 `C-1002` 查看地址归属、时段覆盖带、工单交集、结论与不确定范围。
6. **楼栋映射** → 「新增地址判断」处理 `北岸新城8号楼、12号楼附近`，选 B03+B07 并填写依据。
   - 若该地址已有不同判断，保存前会强制选择「采用本次 / 保留原有 / 合并」，不会静默覆盖。
7. **运行** → 再运行一次（相同截止）→ **运行差异** 显示受影响的投诉与楼栋风险变化。
8. **运行报告** → 报告固定引用运行快照；可复制 Markdown、导出 `.md` 或打印 PDF。

### 探头位置偏差与楼栋风险敏感性（新增）

同一楼层两只探头长期低于邻近探头，既可能是**外墙安装的固定空间差异**，也可能是**探头漂移**，直接把低读数“校正”会抹掉真实的局部停供证据。工具在原始分析之上并行运行两条路线，且**两条路线都不改写原始读数**：

- **路线 A · 固定安装分层的稳健邻近比较（`src/lib/bias.ts`）**：仅在相同供热日、室外温度带宽 ±3℃、双方覆盖率差 ≤ 0.2 的条件下配对，取当日中位数之差，再以段内稳健中位 + MAD 汇总。每个探头按**更换 / 外墙改造 / 重新校准事件时间拆段**，逐点比较证据可在「位置偏差」页逐行回查。
- **路线 B · 含位置与天气协变量的层级模型**：`y = 供热日固定效应(吸收天气) + 楼栋截距 + 外墙/冷朝向/楼层/房间类型固定效应 + 探头随机效应(经验贝叶斯收缩) + ε`，给出 90% MAD 预测区间与适用范围；楼栋探头不足时回退全小区池化并明确标注借用范围，池化仍不足则标记模型不适用。**模型估计永远不被当作实测**。
- **自动校正门控**：位置证据编号、段内有效校准证书、≥3 个可比供热日、持续中位差 ≥ 0.8℃ 且方向稳定、证书示值偏差不与邻近证据反向冲突——任一不满足即调整量为 0，只输出**位置效应/漂移不可区分区间**。
- **三视图**：① 原始视图（原始读数、原始风险，与主分析同版本）② 证据支持的偏差调整视图（仅门控通过段生效）③ 不可区分区间（下界为最有利于供热方解释、上界即原始结论）。设备档案、位置证据、风险计算与报告引用同一运行快照；补证只生成新运行。

| 偏差场景 | 样例证据 | 两条路线下的预期结论 |
| --- | --- | --- |
| 外墙探头（证据齐全） | P-301 一层北向外墙，证书 CAL-301 有效，全窗稳定比 P-302 低约 0.9–1.3℃ | 路线 A 门控通过、调整视图上抬；不可区分区间中漂移分量归零；B01 原始风险与 1/8 短时扰动分类不变 |
| 真实局部停供 | P-802 无持续位置偏差，1/13 立管阀门事件（WO-2002） | 调整量为 0，B03 在三视图下都保持中等风险，停供证据不被抹除 |
| 探头漂移 + 证书过期 | P-602 自 1/10 渐进漂移，CAL-602-EXPIRED 于 2025 年底到期 | 门控拒绝自动校正，只给位置/漂移分量区间与模型预测区间；对齐问题列出 `bias_certificate_expired` |

## 功能与设计要点

### 为什么以「楼栋 × 供热日」为底表

围绕每条投诉截取附近探头，回答的是"投诉发生时有什么证据"；但探头缺失楼栋会被排除，投诉密集区域会主导整体判断。本工具反过来：**先为每栋楼建立按供热日排列的监测覆盖面，再把投诉作为解释线索关联进去**。代价是需要维护楼栋/探头/地址映射，部分投诉会保持未归属——这是有意设计的诚实留白。

### 时间对齐

- **供热日**：每天 06:00 至次日 06:00（可配置），夜间停供不会被拆到两个供热日。
- **读数**：不同上传频率（10 / 15 / 30 分钟）按各自间隔推算应到条数，间隔超过 3 倍视为中断。
- **气象**：30 分钟观测，相邻观测 ≤ 3 小时内线性插值，超出为缺测。
- **工单**：按楼栋别名定位，与低温片段按时间重叠判定。

### 判定路径（确定性规则，非黑箱）

1. **覆盖检查**：日覆盖 ≥ 60%、夜间覆盖 ≥ 50%，否则「覆盖不足」，不参与风险判断。
2. **稳健基线**：每个探头取稳定日的中位数为基线，保留 p20–p80 作为不确定范围。
3. **低温片段**：同时低于舒适阈值 18℃ 且低于自身基线 2℃ 的连续读数片段。
4. **形态判定**：≤ 90 分钟 → 短时扰动；影响探头 ≤ 50% → 局部设备；覆盖多数探头且 ≥ 3 小时、或有停供工单 → 供热不足。
5. **对齐校验**：工单记录停供但读数正常 → 对齐不可靠（不是"无问题"）。
6. **投诉支持度**：有据可查 / 部分支持 / 未获支持 / 无法对齐 / 无法核实 / 未归属。

所有阈值可在「运行」页调整，随运行快照保存；历史运行不受后续修改影响。

### 版本化与可比性

- **导入批次**：保存文件哈希、字段映射、到达时间、覆盖范围与解析问题；原始文本存在本地 IndexedDB，可重新映射字段。
- **登记册版本**：每次修订生成新版本，已完成运行引用原快照。
- **地址判断**：人工确认优先于自动匹配；同一地址出现不同判断时，保存前强制选择保留一方或合并。已完成的运行继续引用原判断。
- **运行快照**：固定输入批次、规则参数、登记册摘要、地址判断摘要与数据截止时点。报告是快照的纯函数。
- **迟到数据**：截止后到达的批次只显示覆盖截止提示，绝不局部刷新图表与结论卡（避免图表指向新分母、结论卡仍用旧分母）。

### 本地存储与隐私

- 所有数据只写入浏览器 IndexedDB（库名 `heat-comparability-console`）。
- 唯一网络请求是同源加载 `public/samples/` 下的样例文件。
- 无埋点、无外部字体/CDN、无上传端点。侧边栏实时显示本地占用。
- 样例中所有门牌、投诉文本、设备编号均为合成数据。

## 项目结构

```
src/
  types.ts               领域类型与默认规则参数
  lib/
    time.ts              供热日时间代数（本地 UTC+8、06:00 边界）
    parse.ts             CSV/JSON 解析、字段映射、坏行与去重统计
    hash.ts              SHA-256（含降级 FNV 兜底）与稳定摘要
    address.ts           投诉地址打分、归属解析、冲突检测
    engine.ts            核心引擎：覆盖底表、基线、片段识别、分类、投诉证据
    runs.ts              运行快照、两次运行差异、迟到数据、报告生成
    ingest.ts            浏览器端导入编排
    format.ts            展示辅助（色板、日期、百分比）
    sources.ts           来源类型元数据
  worker/
    analysis.worker.ts   WebWorker：解析、窗口匹配、基线、大文件分析
    client.ts            类型化 Worker 客户端
    protocol.ts          请求/响应协议
  db/store.ts            IndexedDB 读写（批次、登记册、确认、运行）
  state/store.ts         应用状态、运行生命周期、冲突处理
  components/
    Layout.tsx           应用外壳、导航、忙碌遮罩、通知
    ui/primitives.tsx    Panel/Stat/Chip/Modal/Drawer/Tabs 等
    charts/charts.tsx    覆盖矩阵、24h 证据图、投诉时段覆盖带
  pages/                 来源登记、覆盖对齐、楼栋映射、运行、结果、投诉证据、报告、方法
  test/                  Vitest 单元测试（引擎、解析、地址、快照、报告）
e2e/                     Playwright 端到端验收
scripts/generate-samples.mjs  确定性样例生成器
deploy/nginx.conf        静态服务配置（安全响应头、SPA 回退）
```

## 已知局限

- 室温探头为室内单点测量，不代表楼栋全部住户。
- 探头断线与"住户拔电 / 季节拆除"无法仅由数据区分，工具只报告覆盖率并把归因留给分析员。
- 短时扰动与开窗通风无法从室温曲线本身可靠区分。
- 地址匹配基于名称与别名，缺少行政区划或 GIS 数据时只能做到候选提示，不做强匹配。
- 判断归属需人工维护；地址模糊的投诉会保持未归属。
- 位置偏差的层级模型在每栋探头少于 6 个时只能全小区池化，个体随机效应借用同类型探头信息、预测区间偏宽；模型估计仅用于界定不可区分区间，不作为实测或自动校正依据。
- 稳健邻近比较依赖登记的邻近关系与同栋探头；布局稀疏（如单探头楼栋）或改造后可比日不足时，工具只报告「不可比」，不产生调整视图。
